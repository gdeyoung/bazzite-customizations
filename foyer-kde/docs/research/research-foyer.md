## 0. Identity: what "Foyer" actually is
- Upstream basecamp/omarchy contains NO file/string "foyer" (grep over full clone = 0 hits).

README: "a fork of the first-party omarchy.menu plugin … follows the active Omarchy theme with no configuration"; KRunner-style launcher on SUPER+SPACE.

## 2. Interaction model — UPSTREAM omarchy.menu (verified Menu.qml/MenuModel.js)
Open/close & geometry:
- Opened by keybind via IPC summon (no process spawn per press). Bindings (default/hypr/bindings/utilities.lua): SUPER+SPACE → menu root ("Omarchy menu"); SUPER+CTRL+C capture; SUPER+CTRL+O toggle; SUPER+CTRL+H hardware; SUPER+ESC and XF86PowerOff system; SUPER+CTRL+S share; SUPER+CTRL+R reminder-set; SUPER+CTRL+SPACE / SUPER+CTRL+W background; SUPER+SHIFT+CTRL+SPACE / SUPER+CTRL+T theme; SUPER+SHIFT+code:201 menu root. `default/omarchy/shortcuts` lists routes bound through Hyprland global-shortcut IPC (menu root/apps/capture/toggle/hardware/system/background/theme/share/reminder-set + panels).
- Route = item id (`setup.power`) or alias (`power`); exact id beats alias; app rows never routable; an alias naming an ACTION runs it directly without opening a window (MenuModel.js:203-217; Menu.qml:1019-1035).
- Window = **OverlayWindow**, Wayland layershell namespace `omarchy-menu`, full-screen layer, scrim rectangle behind, click on scrim closes (Menu.qml:1273-1305).
- Card **centered** on open; first search keystroke or submenu move FREEZES the top edge (`freezeCardTop`) so the card grows/shrinks downward only; same moment freezes max rows height for submenus. Close/screen-change unfreezes (Menu.qml:1280-1295).
- Width `Style.space(300)` (520 for screenrecord/font/kernel menus); height content-fitted (margin*2 + header + spacing + rows), capped at **70% of screen height**; overflow folds mid-row with a 55%-row peek as scroll affordance (Menu.qml:133,138-142,184-209).
On open (empty query): children of the summoned route in JSONC order; header placeholder = submenu label + "…" (root "Go…"); focus in search input; cursor on first selectable row (Menu.qml:953-975,1417-1428).
Keys (Menu.qml:1326-1367): typing filters (Util.editsFilter); ↑/↓ ±1 wrap skipping disabled rows; PageUp/Down ±6; wheel scrolls; Enter/Return/**Right** activate (Right drills in); **Backspace or Left on empty filter = up one level** (navStack pop → parent); **Esc = clear filter, then close** (differs from fork); Delete on app row = uninstall confirm dialog (ConfirmDialog, default No). Hover selects only after real pointer movement (PointerMoveGate); click activates. Enter with nothing selectable just parks the cursor; disabled rows dim to 0.4 opacity.
Drill-down: submenus replace the list in the same card; header retitles; navStack history + parent fallback (Menu.qml:830-858). Menu/link rows show "›" chevron (opacity .36). childCount is computed per row but rendered `visible:false`.
Search (MenuModel.js:316-389, Menu.qml:706-783): multi-term **substring** (not fuzzy) — each term must hit nameText (label + leaf-id + aliases + searchTerms; dots/dashes tokenized) OR match a whole word in description; disabled rows excluded. Scored tiers: exact-label-at-root 2 / exact 0 / app-whole-word 0 / label-prefix 10 / label-substring 30 / nameText 40 / description-whole-word 60; menu/link −2, app −5; final score*1000 + depth*25 + source order. Results: current-menu matches first, hairline divider, then deeper "drilldown" matches with parent-path detail ("Appearance › Theme"). First keystroke lazy-loads providers (apps, fonts, kernels…) into the searchable set.
Apps: QML-native provider splicing rows under the `apps` node — id `apps.<desktop-id>`, label=Name, description=GenericName, aliases=[GenericName]+Keywords, image icons, launch with feedback, live DesktopEntries updates; Apps submenu sorted case-insensitively (Menu.qml:365-408,758-772). Filtering (NoDisplay + launcher.hides) lives in the shell's shared AppLibrary (shell/services/PluginAppLibraryApi.qml). **HEAD drift caveat:** current HEAD's `apps` node ALSO carries `action: omarchy-shell omarchy.dock apps` (opens the dock's app grid) and kind inference action→action makes the Apps ROW run that action; app rows are primarily reached via search (or the dock). The fleet's 4.0.4 build may drill in-menu instead — UNVERIFIED which browse behavior ships in 4.0.4. No favorites/recents anywhere upstream.
Other upstream features: bash providers (fonts/power-profiles/kernels/languages) emitting TSV with ✓ current markers, volatile re-run on submenu entry; dmenu select/input mode for scripts; i18n catalogs (default/i18n/<code>/menu.json) with English labels kept as searchTerms; both JSONC files live-watched (FileView watchChanges).

## 6. Guards — dynamic row state (keep for the port)
Upstream (MenuModel.js:413-618): every node may carry `when:` (hide if false), `checked:` (append ✓), `disabled:` (dim+unselectable+✓) — bash expressions evaluated in ONE batched `bash -lc` per reload: 19 known reader commands pre-run in parallel process substitutions; a pacman package+provides snapshot cached in $XDG_RUNTIME_DIR; remaining guards fanned into 8 parallel subshells (400ms→~160ms cold, ~55ms warm); output `<id>:<w|c|d>:<0|1>`; failed/half batches keep the last complete set. This powers Install/Remove "already installed" state and all ✓ marks. Fork keeps when/checked only (no disabled), simpler single-pass batch, and marks its own config rows ✓ from foyer.json instead of bash.

## 7. Foyer fork — interaction model (verified Runner.qml/RunnerModel.js)
- Open: SUPER+SPACE (rebinds via foyer-setup wizard → ~/.config/omarchy/foyer.json `keys` + generated foyer.lua + one pcall line in hyprland.lua; optional second key for the Apps list, default SUPER+ALT+SPACE; `foyer` CLI: toggle|summon|close|refresh|ping|setup|apply + route). Summon payload {"menu": route} same routes as omarchy-menu, plus `sources` and `foyer-settings` pages.
- Window: PanelWindow anchored all edges, transparent, layershell namespace **"omarchy-menu"** (same as upstream), Overlay layer, Exclusive keyboard focus. Location setting: center default or pinned top positions (grows downward).
- **Root with empty query = a bare input line** ("collapsed": no row area — "the whole point of foyer") UNLESS start groups exist: Favorites (pinned, Ctrl+P; ★ shown in searches; reorder Ctrl+↑/↓ on Favorites page; max 30) and/or Recent launches (own launch history, max 50 stored) and/or **menu on start** (default ON): the full Omarchy root tree listed in the results area under the "Omarchy" caption; typing swaps the list for live search.
- KRunner-style caret: typing keeps caret in search box (cursorActive=false; blinking accent caret); Enter runs the TOP hit; Down enters results; Up from first row returns to the box. Esc: clear query → back one level → close at root. Backspace/Left-on-empty = back (plus header back-arrow button). Ctrl+1..9 quick-launch rows 0-8 (COSMIC-style, Shift passes through for alternate actions); Ctrl+P pin/unpin; Ctrl+S Settings; Ctrl+, Sources; F1 Help; Delete = uninstall app (ConfirmDialog). Wheel + PageUp/Down ±6. Hover-after-movement selects; Shift+click = Shift+Enter.
- Search: same substring+tier scoring as upstream PLUS (a) alias-equals tier (action 5 / menu 20), (b) optional **fuzzy** (default ON): query ≥3 chars, letters in order starting at a word boundary, skipped ≤ typed, scored 85+min(9,gaps) — below all other tiers; (c) session aliases ("restart"→Reboot, "sleep", "lock screen", "log out", "power off"…). 120ms debounce; serial-guarded async sources.
- Root search layout: prefix-claimed sources own the list; leading groups (AI) first; menu-tree matches split into **Omarchy / Applications / Session** groups (best-match group leads; each hideable via Sources page); then other source groups; web-search fallback only when nothing matched. In submenus: current-then-drilldown with divider, like upstream.
- 19 sources (foyer/Runner.qml:149): Calculator (`=`, qalc units/currency), Location (`loc:`), Timers ("20 min timer", "in N …"), Control (brightness/volume phrases), DateTime ("time X", today/tomorrow), Commands (`>`, shell history + run), Kill (`kill `), Clipboard (`cb `, incl. images, `cb list`), Snippets (`;name`, copies; Shift+Enter pastes), Emoji (`:fire`), SSH (`ssh ` hosts from config), Trash, Windows (open windows; activate via Hyprland Lua dispatcher), Folders, Files (fzf fuzzy optional), Recent (xbel), Web (`web:` / default engine; webSearchUrl config), Handoffs (custom `prefix Label https://…%s` rows, e.g. gh/mdn/aur; managed in-launcher), AI (`ai:` or `? ` — one-row answer, Enter copies; any OpenAI-compatible endpoint; key never on argv).
- Extra pages injected as menu nodes: Foyer Sources, Foyer Settings (Ctrl+S), Foyer Help (F1, "?" examples), Handoffs, Snippets. Voice: VoxType mic button; dictated phrases normalized ("brave search for x" → "br: x") via VoiceModel.
- Apps in the fork: own AppModel/AppSource (third-party plugins can't reach the shell's shared AppLibrary) reading DesktopEntries directly; NoDisplay filtered + same launcher.hides parsed from $OMARCHY_PATH (AppModel.js:36-58); alphabetical; launch + uninstall support; launches recorded into history.

Launch history/favorites: `~/.local/state/foyer/history.json` (dir 0700, atomic writes, .bak on corruption).
- Follows active Omarchy theme colors/rounding/gaps by default (Color.menu.*, Style.cornerRadius), with fork overrides (opacity, radius, border, accent).

## 9. Keep vs Omarchy-specific (port guidance)
KEEP (product-defining): JSONC tree with dotted-id hierarchy + per-key user-extension merge + live file watching; id/alias route summoning (deep-linkable); tiered substring search with current/drilldown split and scored groups; batched dynamic row state (when/checked/disabled equivalents — map to KShell/systemqueries on KDE); apps spliced from desktop entries with NoDisplay+hides filtering and GenericName/keywords aliases; ✓ current-value rows for provider lists; centered card that freezes its top edge and grows downward, folding mid-row; caret-in-searchbox KRunner flow (Enter=top hit, Down=enter list); Esc/backspace level-back (fork semantics); prefix-claimed sources + grouped results + web fallback; the dmenu-style select mode as a scriptable dialog surface; uninstall-with-confirm on app rows; i18n with English kept searchable.
