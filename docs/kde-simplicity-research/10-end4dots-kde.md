# end-4dots-kde — technical dossier

Fleet question this answers: does a working "full desktop shell on Quickshell, on Plasma 6" exist in late 2026, and what does its existence do to our 2026-11-04 conclusion that Quickshell can only be companion chrome on Plasma?

## 1. Repo Reality

**Identity.** `ladybug-me/end-4dots-kde`, description "dots-hyprland ported to KDE plasma 6", homepage `https://ii.clsty.link` (the illogical-impulse mirror domain run by GitHub user `clsty`, who is also the #2 contributor — the repo looks like a clsty-driven effort under the `ladybug-me` account; identity not independently verified). License GPL-3.0. Created **2026-06-14**, size ~57 MB, wiki enabled. ([API](https://api.github.com/repos/ladybug-me/end-4dots-kde))

**Traction:** 135 stars, 4 forks, 6 watchers as of 2026-11-12. Modest but real for a 5-month-old ricing repo. ([API](https://api.github.com/repos/ladybug-me/end-4dots-kde))

**Activity — the critical nuance.** The repo is a *snapshot import + diverging branches*, not a steady-stream project:

- `main` (default): 100 commits, imported with full upstream history (oldest fetched 2026-05-09); port-specific commits run 2026-06-14 → **2026-06-24** ("Update README.md" is the tip). Essentially frozen since late June. ([commits](https://api.github.com/repos/ladybug-me/end-4dots-kde/commits))
- `dev`: active through **2026-10-23** (repo `pushed_at` 2026-10-23). Recent commits are refactors plus recurring **"sync: caelestia-kde upstream sync"** commits and, on `feat/end4-pc`, a "**major: set pctrade/end4-pC as upstream for shell/**" commit — i.e. the live line of development has re-based its shell onto other KDE-port projects rather than continuing solo. ([dev commits](https://github.com/ladybug-me/end-4dots-kde/commits/dev))
- `feat/end4-pc`: same October activity, a variant branch for a specific machine ("end4-pC").

**Versioning:** exactly one release, `v1.0.0` "Illogical Impulse on KDE Plasma", published 2026-06-17 — one tag, no semver cadence since. ([releases](https://github.com/ladybug-me/end-4dots-kde/releases))

**Issues/PRs:** 6 issues (5 closed, 1 open — [#4 "Panel Visibility - Dodge Windows"](https://github.com/ladybug-me/end-4dots-kde/issues/4), open since 2026-06-21), 2 closed PRs (keyboard-lock OSD indicators; "prefer KDE desktop portal", both 2026-08-27). Low-tracker, chat-elsewhere project (Discord-centric upstream community).

**Contributors:** `end-4` (4107 — inherited history), `clsty` (781), then small drive-by patches (jwihardi, vaguesyntax, H0mire...). So: one primary porter (clsty/ladybug-me), upstream author's history carried in, small long tail.

**Verdict:** not a one-off hack — it shipped a v1.0.0 installer and stayed alive on `dev` for 4+ months — but also not a healthy multi-maintainer project. It's a single-maintainer port that by October 2026 was heavily syncing from `caelestia-kde` and `pctrade/end4-pC` rather than originating features. Treat `main`/v1.0.0 as the artifact worth studying, and the dev-branch upstream-sync pattern as the signal about sustainability.


## 2. What Ships Today

All paths/quotes below are from `main` @ `14e3b785` (the v1.0.0 artifact, June 2026) unless flagged `dev`.

**The whole upstream illogical-impulse Quickshell shell is vendored in.** `src/repo-base/.config/quickshell/ii/` carries the full shell: `shell.qml` (root, two "panel families": `ii` + `waffle`, IPC `panelFamily cycle`), `settings.qml`, `welcome.qml`, `translations/`, and a 40+-singleton `services/` layer — `Ai.qml`, `AppSearch.qml`, `Audio.qml`, `Battery.qml`, `BluetoothStatus.qml`, `Cliphist.qml`, `Notifications.qml`, **`PolkitService.qml`** (Quickshell ships its own polkit agent), `TrayService.qml` (own system tray), `Wallpapers.qml`, `Weather.qml`, `Ydotool.qml`, plus Hyprland-specific ones kept verbatim: `HyprlandData.qml`, `HyprlandKeybinds.qml`, `HyprlandXkb.qml`, `HyprlandConfig.qml`, `Hyprsunset.qml`, `HyprlandAntiFlashbangShader.qml`. ([tree](https://github.com/ladybug-me/end-4dots-kde/tree/main/src/repo-base/.config/quickshell/ii))

So yes: **bar, dock, left/right sidebars, overview, search/launcher, OSDs, on-screen keyboard, notification popups + tray, wallpaper manager, settings app, AI widgets** all ship — as upstream QML, not stubs. README key-features quote: "**Quickshell widgets**: Native KDE integration with modern Qt-based widget system … **Custom KDE bridge**: Quickshell-KDE integration via KWin script for seamless widget interaction … **Custom hyprctl**: Rewritten to integrate with hyprland calls by quickshell". And the honest self-scope: "**NOT**: A replacement for the original Hyprland dotfiles (which are superior for minimal window managers)". ([.github/README.md](https://github.com/ladybug-me/end-4dots-kde/blob/main/.github/README.md))

**KDE-specific layer (what the porter actually wrote):**
- `src/config/quickshell/ii/GlobalStates.qml` + `ReloadPopup.qml` — KDE overrides layered over the vendored shell (`src/config/*` is copied after `repo-base/*` and overwrites it; [scripts/03-deploy-configs.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/03-deploy-configs.sh)).
- The bridge trio: KWin script `src/kwin-script/` **and** `src/kwin/quickshell-kde-bridge/` (both exist on `main`; the installer copies the latter to `~/.local/share/kwin/scripts/`), `src/bin/qs-kwin-bridge.py`, `src/bin/hyprctl` (mock). Verified via [contents API](https://api.github.com/repos/ladybug-me/end-4dots-kde/contents/src?ref=main).
- Matugen theming with KDE templates (`src/config/matugen/templates/kde/` incl. a `kde-material-you-colors` wrapper) — the dual theming path: matugen for Quickshell, `kde-material-you-colors` daemon for Plasma itself.
- A 9-step installer (`scripts/00`–`10`): yay/dnf prereqs, package groups, config deploy w/ backups, KDE settings (Darkly theme, Kvantum MaterialAdw, Bibata cursor, optional **Polonium** tiling, 10 virtual desktops, Meta+1..0 shortcuts, **KDE volume/brightness OSDs disabled**), autostart, services, tweaks. ([scripts/04-deploy-kde.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/04-deploy-kde.sh))

**Functional vs degraded on `main`/v1.0.0:** theming pipeline, bar/sidebars/OSK/notifications/tray run (they're plain Quickshell layer-shell UI). Window-data-dependent features are the weak leg: the Python bridge daemon's systemd unit `src/systemd/qs-kwin-bridge.service` is a **0-byte empty file** on `main`, so `07-services.sh` explicitly skips enabling it, and nothing else autostarts the daemon; meanwhile the `hyprctl` mock implements `binds/monitors/workspaces/activeworkspace -j` but **not** `clients/layers -j` (falls through to printing `Mock hyprctl (Python KDE+Keyd bridge)`). The vendored `HyprlandData.qml` still calls `hyprctl clients -j`. Net: taskbar running-app indicators / overview window lists depend on a daemon nobody starts — exactly matching the bug reports ([#7 "Dock 'hover to reveal' and App Activity not working"](https://github.com/ladybug-me/end-4dots-kde/issues/7), [#10 "Keyboard shortcuts overlapping … launcher is kinda slow"](https://github.com/ladybug-me/end-4dots-kde/issues/10)). The launcher is **fuzzel** (external binary, `src/config/fuzzel/`), not a native Quickshell launcher. Wallpaper: Quickshell's own manager, with README warning "**DO NOT USE KDE WALLPAPER MANAGER**".

**`dev` (Oct 2026) is a different animal:** repo restructured onto the `caelestia-kde` layout (`shell/`, `installer/`, `packaging/`, `docs/architecture/`), ii shell being re-based onto Caelestia C++ plugins; README status: "Installer done. Dots configured. Porting ii to use caelestia plugins." Requirements moved to "**KDE plasma 6 with qt 6.9+ support**", distros Arch/Fedora/Debian-Ubuntu. ([dev README](https://github.com/ladybug-me/end-4dots-kde/blob/dev/README.md))

## 3. Architecture & Runtime

**How Quickshell runs (main/v1.0.0):** plain XDG autostart, not systemd — `~/.config/autostart/quickshell.desktop` with `Exec=bash -c 'sleep 2 && qs -c ii &'` at `X-KDE-AutostartPhase=2` ([scripts/06-autostart.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/06-autostart.sh)). It renders through layer-shell (`PanelWindow` everywhere), which KWin supports since 5.20 — Plasma panels are NOT killed or replaced by script; the user is expected to have the Quickshell bar coexist/remove the Plasma panel manually (no `appletsrc` or panel-hiding logic ships in the repo — the only open issue, [#4 "Panel Visibility — Dodge Windows"](https://github.com/ladybug-me/end-4dots-kde/issues/4), is a user asking for Plasma-style dodge-windows behavior, i.e. panel-window coexistence is still unresolved).

**Input plumbing is the invasive part:** system-wide **keyd** (`/etc/keyd/quickshell.conf`) owns the Super-key semantics (e.g. hold-Super shows workspace numbers — see `GlobalStates.qml`'s `GlobalShortcut { name: "workspaceNumber" }`), and **ydotool** injects synthetic key events for the shell's "OSK"/dispatch needs. The installer adds a udev rule for `/dev/uinput`, adds the user to `input`, and — rough edge — writes a **sudoers NOPASSWD rule for ydotoold**; the shipped `ydotoold.service` even hardcodes `/home/johnlol/...` ([scripts/07-services.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/07-services.sh), [src/systemd/ydotoold.service](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/systemd/ydotoold.service)). This is a genuine "takes over your system" installer, matching upstream illogical-impulse's philosophy.

**Quickshell/Qt versions:** Arch path builds `illogical-impulse-quickshell-git` **pinned to commit `7511545e`** (`pkgver=0.1.0.r1`, pkgrel 8 — an old master pin inherited from upstream's PKGBUILD, *not* a 0.2/0.3 release), with Qt6 + extra deps `qt6-5compat, qt6-multimedia, qt6-positioning, qt6-sensors, qt6-virtualkeyboard, kirigami, kdialog, syntax-highlighting` ([PKGBUILD](https://github.com/ladybug-me/end-4dots-kde/blob/main/sdata/arch-dist/illogical-impulse-quickshell-git/PKGBUILD)). Fedora path installs Quickshell from the **`errornointernet/quickshell` COPR** (the same COPR our fleet knows carries 0.3.2) ([feddeps.toml](https://github.com/ladybug-me/end-4dots-kde/blob/main/sdata/fedora-dist/feddeps.toml)). `dev` requires **Qt 6.9+**.

**Distro assumptions:** Arch-first (installer auto-installs `yay` from AUR if missing — [scripts/01-ensure-prereqs.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/01-ensure-prereqs.sh)); Fedora 42+ secondary via 6 COPRs (`ririko66z/dots-hyprland`, `sdegler/hyprland`, `deltacopy/darkly`, …) and even keeps Hyprland packages in the Fedora dep set; `dev` adds Debian/Ubuntu claims. Python env via `uv` (with `shell.nix` for Nix users) and a **manual MicroTeX build** step for equation rendering ([scripts/02-packages.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/02-packages.sh)). Tested on CachyOS, Manjaro KDE, Fedora 44 KDE per README.


## 4. KWin Bridge Deep Dive

### v1.0.0 design: a three-hop "fake Hyprland" ([DeepWiki 6.1](https://deepwiki.com/ladybug-me/end-4dots-kde/6.1-kwin-script-(quickshell-kde-bridge)), [6.2](https://deepwiki.com/ladybug-me/end-4dots-kde/6.2-python-bridge-daemon-(qs-kwin-bridge.py)))

Because QtWayland clients can't read other windows' geometry/metadata (security model), the port pushes window state **out of the KWin process**:

1. **KWin JS script** ([src/kwin-script/contents/code/main.js](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/kwin-script/contents/code/main.js), 2.1 KB, ~70 lines): `updateWindows()` walks `workspace.windowList()`, filters `normalWindow`, and serializes each window as Hyprland-shaped JSON — `title` (caption), `class` (resourceClass), `workspace: {id: desktops[0].x11DesktopNumber || 1}`, `at:[x,y]` / `size:[w,h]` from `frameGeometry`, `internalId`, `floating: !w.tile`, `fullscreen`, `xwayland`. It pushes via `callDBus("org.kde.qs", "/bridge", "org.kde.qs.bridge", "updateWindows", json)`. Hooks: `windowAdded` (also per-window `frameGeometryChanged`/`desktopsChanged`), `windowRemoved`, `windowActivated`, `currentDesktopChanged`. Note the JSON schema is deliberately Hyprland-`clients`-shaped — the consumers are unmodified upstream QML.
2. **Python daemon** ([src/bin/qs-kwin-bridge.py](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/bin/qs-kwin-bridge.py), 67 lines, python-dbus + GLib): owns bus name `org.kde.qs`, object `/bridge`, method `updateWindows(s)`; validates JSON, caches to `/tmp/qs_kwin_windows.json` (so the UI repopulates after restarts), and **echoes the JSON to stdout**, which the shell's `HyprlandData` service parses line-by-line ([DeepWiki 6.2](https://deepwiki.com/ladybug-me/end-4dots-kde/6.2-python-bridge-daemon-(qs-kwin-bridge.py))). On startup it waits 500 ms, then drives `org.kde.KWin /Scripting` `unloadScript`/`loadScript("quickshell-kde-bridge")` to force the KWin script's initial push past the bus-availability race.
3. **Mock `hyprctl`** ([src/bin/hyprctl](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/bin/hyprctl), ~11.5 KB Python, installed to `~/.local/bin` so it shadows the real binary): implements `binds -j` by **merging `~/.config/kglobalshortcutsrc` + `/etc/keyd/quickshell.conf`** into Hyprland `binds -j` JSON (with a large hardcoded friendly-description table for the Cheatsheet widget), mocks `monitors -j` → `[]`, `workspaces -j` → `[]`, `activeworkspace -j` → `{"id": 1}`, and prints `Mock hyprctl (Python KDE+Keyd bridge)` for everything else.

**Install/registration (main):** the script directory is copied to `~/.local/share/kwin/scripts/quickshell-kde-bridge/` and enabled with `kwriteconfig6 --file kwinrc --group Plugins --key quickshell-kde-bridgeEnabled true` ([scripts/04-deploy-kde.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/04-deploy-kde.sh)); `metadata.json` is a `KWin/Script` KPackage (`X-Plasma-API: javascript`, Id `quickshell-kde-bridge`), so it's also manageable in System Settings → KWin Scripts.

**No `registerShortcut`/kglobalaccel from the shell on main.** Quickshell's `Quickshell.Hyprland.GlobalShortcut` doesn't exist on KWin, so Super-key semantics are handled by **keyd** at system level and the installer registers workspace shortcuts by writing `kglobalshortcutsrc` (kwin group, Meta+1..0). The `dev` branch fixes this properly (below).

**Reality vs docs:** `src/systemd/qs-kwin-bridge.service` is a **0-byte file** on `main` (verified via [contents API](https://api.github.com/repos/ladybug-me/end-4dots-kde/contents/src/systemd?ref=main)), and [07-services.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/07-services.sh) explicitly skips empty units — so on v1.0.0 **nothing starts the daemon**, and `hyprctl clients -j` (which `HyprlandData.qml` calls) is not implemented by the mock. DeepWiki's daemon page claims the service "ensures it starts automatically with the Plasma session and restarts if it crashes" — that is intent, not shipped reality; its shim page likewise claims `clients -j` is "mocked or bridged", which the code contradicts. Symptom corroboration: [#7](https://github.com/ladybug-me/end-4dots-kde/issues/7) (dock hover-reveal + running-app indicators dead), [#10](https://github.com/ladybug-me/end-4dots-kde/issues/10) (16 comments).

**Plasma panel handling:** it doesn't. Nothing touches `plasmashell`, no panel-hiding config ships; Quickshell's layer-shell bar is expected to coexist (you delete the Plasma panel yourself). Dodge-windows coexistence is the **only still-open issue**, [#4](https://github.com/ladybug-me/end-4dots-kde/issues/4). What the port *does* disable is Plasma's own OSDs (volume/brightness) so Quickshell OSDs own that niche ([scripts/10-system-tweaks.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/10-system-tweaks.sh)).

### The `dev` rewrite: why the bridge had to become C++ ([docs/architecture/kwin_port_architecture.md](https://github.com/ladybug-me/end-4dots-kde/blob/dev/docs/architecture/kwin_port_architecture.md))

The maintainer's own post-mortem on the v1.0.0 bridge: "*too many IPC hops, prone to lagging, required a background daemon, and heavily restricted the shell from using KDE's native capabilities*". An interim approach (QProcess `qdbus6` calls injecting throwaway KWin scripts) was also abandoned. Current `dev` architecture:

- **`KWinActiveWindowBridge`** — C++ Quickshell plugin singleton binding the **`plasma-window-management` Wayland protocol** directly (`PlasmaWindows`): live `activeWindow`/`windowList`/`activeOutputName`, plus invokables `focusWindow/closeWindow/minimizeWindow/maximizeWindow/setFullscreen/raiseWindow/setWindowDesktop`. No D-Bus, no KWin script, no daemon for window state.
- **`KWinWorkspaceState`** — virtual-desktop state over the Virtual Desktop Manager D-Bus API + **trackpad swipe tracking via a `QLocalSocket` server** fed by a **compiled KWin Effect** (`shell/kwin-effects/workspace-tracker/`, `org.caelestia.Workspaces`). The effect's header is candid about *why* it must live in the compositor: "*There is no unprivileged way to do this from outside: plasma-window-management can move a window between desktops but not between screens, and the D-Bus surface has nothing for it either. Inside the compositor it is one call.*" (`SendToOutput`) ([workspace_tracker.hpp](https://github.com/ladybug-me/end-4dots-kde/blob/dev/shell/kwin-effects/workspace-tracker/workspace_tracker.hpp)).
- **`GlobalShortcut`** — C++ QML component registering shortcuts **through kglobalaccel natively**; plus `GlobalShortcutDispatcher`/`KeybindsModel` singletons with a shortcut **collision index** (`stolen-shortcuts.json`) and `~/.config/caelestia/keybinds.json` user overrides. `Shortcuts.qml`'s `CustomShortcut` wrapper picks `Quickshell.Hyprland.GlobalShortcut` or `Caelestia.GlobalShortcut` at runtime — one shell source, two compositors.
- QML side: `shell/services/Kwin.qml` is a Hyprland-API-shaped facade over the C++ singletons (`activeWindow`, `windowList`, `workspaces`, `monitors` mocked from `Quickshell.screens`, `addresses` with `0x`-prefix compatibility), so upstream ii modules keep working.

**Fleet takeaway from the evolution:** pure-QML Quickshell + JS KWin script + D-Bus daemon was good enough to *demo* window-aware widgets on Plasma 6, but the moment the port got serious it had to compile C++ against `plasma-window-management` and KWin effect/plugin APIs (and now requires Qt 6.9+). Every integration wall we predicted in the 2026-11-04 research (window management, global shortcuts, compositor-internal actions) shows up here as a compiled component.

## 5. Dependencies & Packaging

- **Out-of-tree Quickshell modules: none.** The ii config is vendored in-repo. `.gitmodules` declares upstream's `end-4/rounded-polygon-qmljs` submodule, but at the legacy `dots/…` path that doesn't exist in this tree — vestigial, not fetched ([.gitmodules](https://github.com/ladybug-me/end-4dots-kde/blob/main/.gitmodules)).
- **Quickshell itself is a build-time system dependency**, not bundled: Arch path compiles `illogical-impulse-quickshell-git` from a **pinned upstream commit** (`7511545e`, pkgver `0.1.0.r1`) with a broad Qt6 set (5compat, multimedia, positioning, sensors, virtualkeyboard, wayland) **plus kirigami, kdialog, syntax-highlighting** ([PKGBUILD](https://github.com/ladybug-me/end-4dots-kde/blob/main/sdata/arch-dist/illogical-impulse-quickshell-git/PKGBUILD)). Fedora path: `dnf` groups from 6 COPRs, Quickshell from **`errornointernet/quickshell`** ([feddeps.toml](https://github.com/ladybug-me/end-4dots-kde/blob/main/sdata/fedora-dist/feddeps.toml)). The pin predates the 0.2/0.3 release line — the shell targets an old master snapshot, so our fleet's 0.2.1/0.3.2 packages are *newer* than what the port was tested against.
- **No distro packaging of the port itself**: no AUR package, no COPR, no Nix flake (only `sdata/uv/shell.nix` for the Python env). Installation is `git clone` + `setup.sh`, which auto-installs `yay` on Arch ([scripts/01-ensure-prereqs.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/01-ensure-prereqs.sh)), builds MicroTeX manually, writes udev + sudoers rules, and runs `makepkg` from `sdata/arch-dist/`. `dev` inherits `caelestia-kde`'s `packaging/` layout (unexamined in detail).
- **Python runtime**: `uv`-managed (`sdata/uv/requirements.txt`) for the daemon-side scripts (dbus, GLib via system python — note `qs-kwin-bridge.py` imports system `dbus`/`gi`, not the uv env, another rough edge).
- **Bazzite/fleet fit**: the *artifacts* are all user-space (KWin script in `~/.local/share/kwin/scripts`, QML in `~/.config/quickshell`, binaries in `~/.local/bin`) and could be extracted without `rpm-ostree` layering — but the *installer* is exactly what our porting rule forbids (sudo, udev rules, sudoers NOPASSWD, makepkg builds, `/etc/keyd` config). Cherry-pick files, never run `setup.sh` on the tower.


## 6. Feature Gap vs the Hyprland Original

Upstream reference: [end-4/dots-hyprland](https://github.com/end-4/dots-hyprland) (16.6k stars, "Usability-first dotfiles", Quickshell-based illogical-impulse, Hyprland 0.55-era with Lua config). Upstream headline features per its [README](https://github.com/end-4/dots-hyprland/blob/main/.github/README.md): "*Overview: Shows open apps with live previews; AI: Gemini, Ollama, and more; QoL: screen translation, anti-flashbang, Google Lens; Material themes…*".

| Area | On the KDE port (main/v1.0.0) | Status |
|---|---|---|
| Bar, dock, sidebars, search, cheatsheet, OSK, notifications, tray, wallpaper manager, settings app, AI widgets | Vendored upstream QML, run as layer-shell on KWin | **Ported** (UI-identical) |
| Material You theming | matugen (QS side) **plus** `kde-material-you-colors` + Darkly + Kvantum/MaterialAdw (Plasma/Qt-app side) | **Ported + re-implemented natively** — dual pipeline is the port's own invention |
| Window management / tiling | KWin + optional **Polonium** script (installer off by default) | **Replaced natively** (vs Hyprland tiling+windowrules) |
| App launcher | **fuzzel** (external, `src/config/fuzzel/`) — not a Quickshell/KRunner replacement | **Swapped out** |
| Lock/idle | `hyprlock`/`hypridle` configs ship in `src/config/hypr/` as leftovers; Plasma's kscreenlocker/powerdevil actually handles it | **Dropped in favor of Plasma** |
| Overview live window previews | Bridge supplies geometry/metadata JSON only — **no thumbnail/screencopy pathway ships**; window lists themselves were broken on main (empty daemon unit) | **Degraded** (previews likely absent; not directly tested) |
| Global shortcuts (Super semantics) | keyd + `kglobalshortcutsrc` writes instead of Hyprland binds; merged for display by the hyprctl mock | **Re-implemented, clunkily** (issue [#10](https://github.com/ladybug-me/end-4dots-kde/issues/10): overlaps with stock KDE shortcuts, slow launcher) |
| Gestures (trackpad workspace swipe) | Not on main; `dev` needed a **compiled KWin effect** to get swipe offsets | **Dropped → later C++** |
| Anti-flashbang shader, Hyprsunset night light | `HyprlandAntiFlashbangShader`/`Hyprsunset` services still referenced (even `dev` `shell.qml` calls `Hyprsunset.load()`) — Hyprland-compositor features, at best no-ops | **Dropped/vestigial** |
| XKB layout per-device, special workspaces, dynamic workspaces | Fixed 10 desktops via `kwinrc`; `dev`'s `Kwin.qml` mocks `lastSpecialWorkspace`, `kbLayout` | **Dropped/mocked** |
| Portals | PR "prefer KDE desktop portal" (merged 2026-08-27) — moved from xdg-desktop-portal-hyprland/gtk | **Re-implemented natively** |
| Installer reach | Arch + Fedora (+Debian/Ubuntu claimed on dev) vs upstream's multi-distro via clsty's scripts | **Sub-set** |

Net: the port is faithful on *chrome* (widgets/theming) and honest about dropping *compositor-adjacent* features — README says outright the original is "superior for minimal window managers". The genuinely new engineering is the Plasma theming duplication (matugen ↔ kde-material-you-colors) and the KWin bridge; everything else is upstream QML carried over with Hyprland service shims.

## 7. Community Reception

Public coverage is **thin** — which is a finding in itself:

## 9. What The Fleet Can Steal (Omarchy→Plasma porting lessons)

Context for these lessons: our 2026-11-04 research concluded Quickshell cannot *replace* Plasma panels (KRunner/GHNS/KConfigXT losses) and only works as companion chrome on a free screen edge; the tower runs Bazzite with libkwin 6.8.2, stock `quickshell-0.2.1` (+ COPR 0.3.2 available), user-space-only porting rule.

1. **The conclusion holds — now with a shipped counterexample attempted and partially failing.** This is the most complete public attempt to run a *full* Quickshell desktop shell on Plasma 6, and its history maps 1:1 onto our predicted wall: layer-shell **chrome worked immediately** (the entire upstream ii widget set runs vendored), while everything compositor-adjacent needed non-Quickshell machinery — window state (KWin JS script → later C++ `plasma-window-management` plugin), global shortcuts (keyd + `kglobalshortcutsrc` edits → later C++ kglobalaccel component), swipe gestures (compiled KWin effect), cross-monitor window moves (compositor-internal only, per their own comment). Notably they **never attempted a Quickshell launcher** — they used fuzzel; KRunner stays Plasma's. No GHNS/KConfigXT equivalent appears anywhere either.
2. **Zero-compile window-state recipe (steal this):** a ~70-line `KWin/Script` KPackage (`metadata.json` + `main.js`) that serializes `workspace.windowList()` and `callDBus`-pushes it to a session-bus service, enabled with `kwriteconfig6 --file kwinrc --group Plugins --key quickshell-kde-bridgeEnabled true`, installed under `~/.local/share/kwin/scripts/` — fully user-space, survives our no-layering rule. Pair with their `unloadScript`/`loadScript` reload-on-start trick to force an initial push. ([main.js](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/kwin-script/contents/code/main.js), [04-deploy-kde.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/04-deploy-kde.sh))
3. **Exact kwriteconfig6 keys to mute Plasma's OSDs** when a Quickshell OSD owns an edge: `plasmarc [OSD] Enabled/ShowOnActiveScreen=false`, `plasmanotifyrc [Notifications] LoudnessChangedOSD=false`, `powerdevilrc [BrightnessControl] showOSD=false` + `[AC] brightnessosd=false`, `kdeglobals [KDE] OSDEnabled=false` ([10-system-tweaks.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/10-system-tweaks.sh)).
4. **Dual Material-You theming pattern:** matugen templates for the Quickshell side + `kde-material-you-colors` + Darkly/Kvantum(MaterialAdw) so Plasma's own frames track the wallpaper palette — their `src/config/matugen/templates/kde/` is a copy-paste seed. Also: "DO NOT USE KDE WALLPAPER MANAGER" — let the QS side own the wallpaper or theming desyncs.
5. **Cheap shortcut-awareness:** parsing `kglobalshortcutsrc` with plain `configparser` + a modmask table (Meta=64, Ctrl=4, Alt=8, Shift=1) is enough to feed any "shortcut cheatsheet" widget without touching kglobalaccel ([src/bin/hyprctl](https://github.com/ladybug-me/end-4dots-kde/blob/main/src/bin/hyprctl)).
6. **Launch pattern:** plain XDG autostart `.desktop` (`Exec=bash -c 'sleep 2 && qs -c ii &'`, `X-KDE-AutostartPhase=2`) — no systemd unit needed for the shell; simple and restartable. ([06-autostart.sh](https://github.com/ladybug-me/end-4dots-kde/blob/main/scripts/06-autostart.sh))
7. **Anti-patterns confirmed costly:** shipping an empty systemd unit (daemon silently never runs → taskbar/overview features dead on v1.0.0); a mock binary returning non-JSON for unimplemented subcommands; hardcoded `/home/johnlol` paths; system-wide keyd takeover colliding with stock KDE shortcuts (issue #10's 16 comments); sudoers NOPASSWD for an input-injection daemon. On Bazzite we'd respect the existing kglobalaccel namespace and avoid keyd entirely.
8. **Version floor check:** the port targets a *pre-0.2* Quickshell snapshot (with kirigami/kdialog extras); our stock 0.2.1 / COPR 0.3.2 are already ahead — Quickshell versioning is not a blocker for our companion-chrome work.
9. **If we ever need first-class window control:** `plasma-window-management` gives an *unprivileged* C++ Quickshell plugin read-access plus `focusWindow/closeWindow/minimizeWindow/maximizeWindow/setFullscreen/setWindowDesktop` — only cross-output moves genuinely require a KWin effect ([kwin_port_architecture.md](https://github.com/ladybug-me/end-4dots-kde/blob/dev/docs/architecture/kwin_port_architecture.md)). That's the honest capability frontier for user-space Plasma shells in late 2026.
10. **Coexistence seam still unsolved:** panel dodge/auto-hide vs maximized windows is their only open issue, open ~5 months — more evidence that "companion chrome on a free edge" (not bar-replacement) is the only battle-tested deployment shape on Plasma.
